### C.2 Dimensions (commits `b382cf7` through `3c09c0c`)

Eight dimension sprints, one per §6 axis. Each sprint adds a check in `EvaluateAccess` that reads a target-side scoping field AND a caller-side context field. Absent context on a scoped target refuses fail-closed with the specific §14 reason.

- **035 access_group** (§6.2) — target `required_access_group` vs caller `access_groups`; refuse `access_group_missing`. B-Q-74 answered: fields on the caller-context object, not a record. Coupling verified — 5 tests red on suppression.
- **036 customer scope** (§6.3) — target `customer` vs caller `customer_context`; refuse `customer_scope_mismatch`. B-Q-75 answered: customer on Shipment / ShipmentLine / GeneratedReport, no new Order record.
- **037 program scope** (§6.4) — target `program` vs caller `program_context`; refuse `program_scope_mismatch`.
- **038 contract scope** (§6.5) — target `contract` vs caller `contract_context`; refuse `contract_scope_mismatch`. B-Q-76 answered: contract on Shipment + GeneratedReport, not on Run. Distinct-from-customer test proves the two dimensions are not proxies.
- **039 factory node** (§6.6) — target `originating_factory_node` vs caller `factory_node_context`; refuse `factory_node_scope_mismatch`.
- **040 record type + report type** (§6.7 + §6.9, folded) — profile whitelists on `allowed_record_types` and `allowed_report_types`. When a caller passes `visibility_profile`, the profile whitelist decides; unregistered profile refuses `access_context_malformed`; a record type not in the whitelist refuses `record_type_restricted`; a GeneratedReport's report_type not in the whitelist refuses `report_type_restricted`.
- **041 support/admin context** (§6.10 / §7.10) — the biggest dimension sprint. New `SupportSession` record with `open/closed` state machine, `OpenSupportSession` + `CloseSupportSession` operations, `SUPPORT_SESSION_OPENED` + `SUPPORT_SESSION_CLOSED` events, `support_session_management` authorization rule. `EvaluateAccess` reads `support_admin_context`; session must exist, be open, cover the target in its scope, be in time. Refuses `support_context_missing` (nonexistent, closed, out-of-scope) or `support_context_expired` (time_window elapsed). Support is opt-in — a caller with no `support_admin_context` is untouched.
- **042 service-account scope** (§6.11) — caller carries `service_account_scope: { processing_actions?, disclosure_actions? }`. Processing permission does NOT imply disclosure permission — the load-bearing §18 distinction (service processing is not human disclosure). Refuse `service_scope_denied`. Discrimination test uses a report_type in the profile whitelist so the refusal lands on the service-scope check, not the profile whitelist.

Every dimension sprint kept whole-bench cross-driver diff-to-zero over 37 scenarios green — no existing record carries any new scoping field, so every check landed dormant for existing traces.

## Techniques the arc exercised

Every sprint applied at least one; the phase applied all of these:

1. **Fail-closed law** (Addendum A2, third recurrence). Every new required input either passes or refuses; undefined is refusal. Each fail-closed guard names its specific §14 failure class — never generic `authorization_denied`.
2. **Coupling mutation** (Addendum A3, practice #3). Every load-bearing guard proven red-capable by suppressing it in-session and observing specific tests go red, then restoring. Applied at sprints 031, 032, 035, and again in the red-team pass on 049.
3. **Same-word audit** at both authoring passes. The mapping pass (sprint 029) surfaced twelve `new-vocabulary` proposals; the pack (sprint 030) reduced them to one new record by asking "do we already have a word". Nothing invented.
4. **Bidirectional registry check** (practice #20, sprint 019). `tests/access/reason-codes-registered.test.ts` proves every §8.3 name resolves in the registry (forward) and every registry entry cites a spec section (reverse).
5. **Opt-in on target-side scoping fields** (new practice #33). Every dimension check is dormant on records that carry no scoping field; existing traces preserved automatically; new records that add a scoping field get the enforcement, and callers without the matching context refuse fail-closed.
6. **Draft-all-cards-up-front / execute-auto-within-phase** (new practice #32). All 24 cards drafted in `1f919ff` before execution. Amended in place when a card's shape shifted (sprint 040 folded record-type and report-type; sprint 041 grew into a full SupportSession lifecycle). No per-card review pause.
7. **Provenance kept followable** (practice #7). `SUMMARY_SHAPES` in `visibility.ts` cites the pack yaml as its source. Every reason code cites its spec section. Every failure class either `maps_to` an existing class or declares `new: true`.
8. **Distrust-the-green** (Addendum A through-line). The red-team pass on Phase C found three real defects — none in the code, all in claims about the code. Fifteen straight increments now have never come back empty on adversarial review.
9. **Diff-to-zero is fidelity, not regression** (new practice #34, from the red-team). Recorded so the next kit revision does not repeat the overstatement.
