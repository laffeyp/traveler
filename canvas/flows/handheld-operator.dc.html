VF-048 scenario steps walked · presentation_alias threaded from present to install
  1. ScanInventoryView. Operator scans the InventoryItem label. Classifier returns presence_asserting because a run step is active and the decoded record is InventoryItem (per scan-classifier.ts:66).
  2. Primary "Present at station" fires PresentInventoryAtStation (rule physical_presence, required_idempotency_key). New Presentation in state presented at station-B4 with intended_operation InstallInventory and presentation_purpose production_install.
  3. RunStepView. BindPresentedItemToRunStep fires (rule presentation_binding). Presentation → bound to the run step.
  4. InstallInventoryView. InstallInventory(world, input) fires with presentation_alias on the input object. The presentation branch (sprint 095) validates the bound Presentation and calls ConsumePresentation in-process inside the same snapshot. Presentation → consumed. InventoryItem → installed. Event INVENTORY_INSTALLED carries presentation_id.
