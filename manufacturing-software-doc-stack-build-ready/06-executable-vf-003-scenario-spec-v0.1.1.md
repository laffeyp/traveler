## 0.1 Why v0.1.1 exists

v0.1.1 corrects the executable semantics of the first VF-003 draft.

The main correction is the quality/rework path:

```text
v0.1 incorrectly had both:
  CompleteRework -> VERIFICATION_PENDING
  RequireVerification -> VERIFICATION_PENDING

v0.1.1 removes RequireVerification from VF-003.

VF-003 is a rework path:
  RecordDisposition
  StartRework
  CompleteRework
  VerifyRework
  CloseNonconformance
```

In VF-003:

```text
CompleteRework emits REWORK_COMPLETED and VERIFICATION_PENDING.
VerifyRework emits VERIFICATION_COMPLETED.
There is exactly one transition into verification_pending.
```

v0.1.1 also applies executable-precision fixes:

```text
1. Add ReserveInventory for valve_body_001.
2. Set valve_body_001 final state to in_wip.
3. Clarify that the dependency table is highlighted, not complete.
4. Make assertion counts generated by compiler/runtime instead of hardcoded.
5. Clarify CompleteRunSteps as a Run-level completion operation.
6. Clarify event ordering when timestamps are equal.
7. Clarify customer_viewer access mapping.
8. Add late-evidence-specific close assertions.
```

